# نظام مقعد — الإصدار 1.0

[تنزيل حزمة XAMPP الكاملة مع مكتبات PDF وExcel](downloads/maqad-xampp-v1.zip?raw=true)

حزمة التنزيل جاهزة للتثبيت وتتضمن `vendor`. عند استنساخ مصدر المستودع مباشرة، نفّذ `composer install --no-dev --prefer-dist` لتجهيز المكتبات.

نظام عربي للخرائط الامتحانية، بالأخضر والأبيض، يعمل على PHP وMySQL / MariaDB ضمن XAMPP، مع مكتبات PDF وExcel مرفقة للعمل محليًا دون اتصال أثناء الاستخدام.

المواصفات المرجعية هي **التحليل الذي أرسله المستخدم** والمحفوظ في `docs/user-requirements.txt`. لم يمكن فتح YouTube مباشرة من بيئة التطوير؛ لذلك هذه نسخة مستقلة تنفذ الوحدات والقواعد المعلنة في التحليل، ولا يُدّعى إثبات تطابقها بنسبة 100% مع كل سلوك في النظام المصوّر أو وظائفه غير المعروضة.

## التثبيت على XAMPP / Windows

1. استخدم XAMPP بنسخة PHP **8.2 أو أحدث، 64 بت**. شغّل Apache وMySQL.
2. فك الحزمة وضع مجلد `maqad` داخل `C:\xampp\htdocs\maqad`، بحيث يكون `index.php` داخل هذا المجلد مباشرة. لا تستبدل مجلد ترفيع أو قاعدته؛ مقعد تطبيق مستقل.
3. من phpMyAdmin أنشئ قاعدة باسم `maqad` وترميز `utf8mb4_unicode_ci`.
4. انسخ `config.example.php` إلى `config.php`. عدّل مستخدم MySQL وكلمة مروره والمنفذ إذا لزم. المثال root دون كلمة مرور مخصص لبيئة XAMPP المحلية؛ يمكن تخصيص مستخدم لهذه القاعدة.
5. افتح `check_windows.bat` للتحقق من PHP والامتدادات والمكتبات. الحزمة الكاملة تتضمن `vendor` ولا تحتاج تشغيل Composer.
6. افتح `http://localhost/maqad/` من الحاسبة نفسها. أدخل اسم المؤسسة والجامعة والعام الدراسي واسم المدير اللاتيني وكلمة مرور لا تقل عن 12 حرفًا. تنشئ التهيئة الجداول وتغلق بعد إنشاء الحساب.
7. سجل الدخول وابدأ بالهيكل الدراسي، ثم القاعات والطلبة والمراقبين، ثم الجدول والخرائط. لا توجد كلمة مرور افتراضية أو بيانات طلبة تجريبية في الحزمة.

يجب تفعيل امتدادات PDO MySQL وmbstring وgd وzip وdom وsimplexml وxmlreader وxmlwriter وfileinfo وiconv في PHP. مكتبات PDF وExcel تعتمد عليها. للأحجام الكبيرة يوصى بـ`memory_limit=512M`، و`upload_max_filesize=20M`، و`post_max_size=24M` في `php.ini`، ثم إعادة تشغيل Apache.

مجلد `storage` يحتاج صلاحية كتابة لحساب PHP لتخزين مفتاح النسخ الاحتياطية وملفات PDF المؤقتة. لا تنقل مفتاحًا تجريبيًا؛ يُولد محليًا عند التهيئة. مجلدات `app` و`database` و`vendor` و`storage` تتضمن ملفات `.htaccess` لمنع الوصول المباشر عبر Apache. خادم PHP المدمج للاختبار المحلي فقط. عند إتاحة البوابات عبر الشبكة يلزم تجهيز HTTPS والتحقق من عمل حماية هذه المجلدات قبل الإتاحة.

## دورة العمل

### 1. الهيكل الدراسي والمؤسسات

- مؤسسات مستقلة بحساباتها؛ حساب المستخدم مرتبط بمؤسسة واحدة ولا يعرض بيانات المؤسسات الأخرى.
- يمكن للمدير إنشاء مؤسسة جديدة بحساب مدير مستقل، ثم الدخول بحسابها لإدارتها.
- أعوام دراسية، أقسام / مدارس، مراحل مرتبطة بالأقسام، ومواد مرتبطة بالقسم والمرحلة.
- إضافة وتعديل وحذف السجلات غير المرتبطة. تمنع العلاقات حذف البيانات المستخدمة أو نقل مرحلة أو مادة إلى قسم آخر وهي مرتبطة بترشيحات أو طلبة.
- محدد العام أعلى الشاشة يفصل قوائم الطلبة والفترات. بيانات القاعات والمراقبين مشتركة داخل المؤسسة عبر الأعوام.

### 2. القاعات والمقاعد

رقم القاعة واسمها والبناية والطابق، عدد الصفوف والأعمدة، السعة المسموحة، الحالة (متاحة / احتياطية / محجوزة)، موضع السبورة والمدخل وعدد المراقبين المطلوب.

تُنشأ شبكة حتى 30 صفًا × 20 عمودًا. من محرر القاعة اضغط حالة الموقع للتبديل بين مقعد نشط وممر ومعطّل، وحدد مواقع الوصول الملائمة، ثم احفظ. ترقيم المواقع ثابت ولا يختفي أثر المقعد عند تعطيله. السعة الفعلية هي الأقل من المقاعد النشطة والسعة المسموحة.

تعديل هندسة قاعة مرتبطة بتوزيع قائم مقفل. افتح المسودة وأفرغها أولًا أو أنشئ قاعة جديدة عند تغيير الهندسة؛ النسخ التاريخية تحتفظ بالشكل القديم، لكن استعادتها للتعديل لا تُقبل إذا لم تعد مقاعدها موجودة.

### 3. الطلبة والاستيراد

رمز الطالب، اسمه، القسم والمرحلة، الدراسة صباحي/مسائي، الشعبة، الحاجة إلى وصول ملائم، والحالة. الرمز فريد داخل المؤسسة والعام.

نزّل قالب Excel من شاشة الطلبة. يدعم الاستيراد **XLSX أو CSV UTF-8**، الورقة الأولى فقط، حتى 5000 طالب و5 ميغابايت للملف، ومحتويات XLSX غير المضغوطة حتى 30 ميغابايت. الأعمدة بالترتيب:

```text
code,name,department,stage,shift,section,needs_access
```

القسم والمرحلة يجب أن يكونا معرفين مسبقًا. الدراسة `صباحي` أو `مسائي`، وحقل الوصول `0` أو `1`. يُرفض الملف كله عند صف مكرر أو ناقص أو غير صحيح؛ لا تتخطى العملية أخطاء صامتة. عند استعمال أكواد ذات أصفار بادئة خزّن خلاياها كنص في Excel.

من شاشة «أماكن الجلوس» يمكن البحث بالاسم أو الرمز وإظهار المادة والفترة والقاعة والبناية والمقعد. تصدير قوائم الطلبة إلى XLSX يحفظ النصوص كقيم نصية ولا يشغلها كصيغ Excel.

### 4. الفترات والترشيح

حدد البداية والنهاية بتوقيت بغداد، والدور والكورس، وتصنيف النظام (فصلي / سنوي / بولونيا)، والقاعات المسموحة إن أردت قصر التوزيع عليها. الحد الأقصى للفترة 24 ساعة.

رشّح مجموعة المادة حسب القسم والمرحلة، مع مرشحي الدراسة والشعبة، أو اختر طالبًا منفردًا. لا يمكن ترشيح الطالب لمادتين في فترة واحدة أو فترتين متداخلتين. الفترات المتتابعة دون تداخل مسموحة.

تحميل مادة من مرحلة أخرى في القسم نفسه يحتاج اختيار الطالب المنفرد، وتأكيد تحميل المادة وكتابة مرجعها. لا يُستنتج الاستحقاق من الساعات أو المعدلات؛ الترشيح هو المصدر الإداري لأهلية الامتحان.

لا تعدّل زمن الفترة أو قائمة مرشحيها مع وجود توزيع؛ أفرغ المسودة مع حفظ نسخة أولًا. تعديل الأهلية الدراسية أو الوصول أو النشاط لطالب مرتبط بترشيح قائم يحتاج إزالة الترشيح من المسودات أولًا. التقارير المعتمدة التاريخية تبقى محفوظة.

### 5. توزيع الطلبة

- طالب واحد لكل مقعد ومقعد واحد لكل طالب في الفترة، بقيود UNIQUE داخل MySQL بالإضافة إلى فحوص التطبيق.
- المقاعد المعطلة والممرات والقاعات المحجوزة مستبعدة. لا تتجاوز الخوارزمية حصة القاعة حتى لو بقيت مواقع نشطة أخرى.
- القاعة المشغولة في فترة زمنية متداخلة مستبعدة كليًا من الفترة الأخرى.
- الطالب ذو حاجة وصول لا يوضع في مقعد غير مخصص لها.
- التجاور اختياري: بدون فصل، أو يمين/يسار، أو يمين/يسار وأمام/خلف. المجموعة هي المادة أو القسم.
- الفصل التفضيلي يقلل التجاور محليًا ويعرض المتبقي كملاحظات. الفصل الإلزامي لا يحفظ حلًا يخالفه.
- يجرب المحرك القاعات العادية، بترتيب السعة ثم المعرف، قبل الاحتياطية. يمكن أن تتطلب سياسة الفصل أو الوصول قاعة إضافية رغم كفاية العدد المجرد للمقاعد.
- المحرك مستقل عن الواجهة؛ يستخدم بحث قيود مع ترتيب ثابت، فتتكرر النتيجة عند اكتمال البحث بالمدخلات نفسها. ليس إثباتًا للأمثلية العالمية أو أقل عدد قاعات بين جميع التركيبات.
- حد البحث 5 ثوانٍ و80000 عقدة. عند بلوغه تظهر رسالة «لم يُحسم»؛ لا يعني ذلك إثبات استحالة الحل، ولا يُحفظ توزيع ناقص. يمكن توسيع القاعات أو استعمال الفصل التفضيلي بعد مراجعة السياسة. حدود الاستيراد ليست ضمانًا لزمن حل كل مسألة فصل إلزامي كبيرة.

يمكن نقل طالب يدويًا إلى مقعد شاغر بعد فحص القيود نفسها. تكرار توليد المقاعد أو النقل اليدوي يلغي توزيع المراقبين الحالي في المسودة لأن القاعات المشغولة قد تتغير؛ أعد توليدهم قبل الاعتماد.

### 6. المراقبون

الاسم واللقب والقسم والأهلية للرئاسة والمراقبة أو المراقبة فقط، والعبء السابق بالدقائق. سجّل فترات عدم التوفر والالتزامات الرسمية؛ لا يقبل استثناءً يصطدم بتكليف قائم قبل استبداله.

التوزيع يخصص رئيس قاعة واحدًا لكل قاعة مشغولة، وبقية العدد المطلوب مراقبين. يمنع تكرار المراقب في الفترة أو تكليفه في فترة متداخلة. تُراعى الاستثناءات والنشاط وأهلية رئيس القاعة.

ترتب الاختيارات بحسب **الدقائق المسندة + العبء السابق**، مع كسر التعادل بالمعرف، لتقليل تفاوت الأعباء دون ادعاء إثبات الحل الأمثل رياضيًا. الفترات المتتابعة مسموحة. يمكن استبدال مراقب ببديل صالح داخل المسودة ويُحفظ التغيير في سجل النسخ.

### 7. الاعتماد والنسخ

المدير وحده يعتمد الخريطة بعد فحص اكتمال المقاعد والمراقبين والأهلية والتعارضات والسعة والوصول والفصل الإلزامي. تُحفظ لقطة كاملة للتقارير المعتمدة، بما فيها الأسماء والقاعات والمقاعد والمراقبون، وتُقفل التغييرات.

يمكن للمدير إعادة الفتح بسبب مسجل. تُسحب النتائج من البوابات مؤقتًا إلى إعادة الاعتماد. كل توليد ونقل واستبدال واعتماد وإعادة فتح يسجل نسخة وسجل عملية. يمكن استعادة نسخة قديمة **كمسودة** فقط إذا اجتازت القيود مقابل المرشحين والمقاعد والتوفر الحاليين؛ وإلا تتراجع العملية دون فقد التوزيع الحالي.

قفل صف المؤسسة داخل معاملات الكتابة يسلسل العمليات المتزامنة قبل فحص التعارضات وحفظها. التوزيع والحفظ والتدقيق عملية واحدة لا تترك نتيجة جزئية عند الفشل.

### 8. بوابتا الطالب والمراقب

من سطر الشخص اضغط «رمز البوابة». يظهر رمز عشوائي شخصي مرة واحدة لتسليمه لصاحبه؛ لا يُخزن نص الرمز في القاعدة. إصدار رمز جديد يلغي السابق.

في صفحة البوابة يختار الشخص طالبًا أو مراقبًا ويدخل رمزه. تظهر **تكليفاته أو مقاعده المعتمدة فقط**. لا يوجد استعلام عام بالاسم أو الرقم، ولا وصول بتغيير رقم طالب في URL. يستطيع الطالب طباعة نتيجته الخاصة. لا تعرض البوابة مسودات أو أشخاصًا آخرين.

### 9. التقارير

خريطة القاعة الهندسية، قائمة القاعة، الخريطة الشاملة، خريطة المراقبين، ملخص المراقبات، بطاقة الطالب، تقرير التعارضات، وتقرير السعة.

المعاينة والطباعة وPDF عربي عبر mPDF وXLSX عبر PhpSpreadsheet. يدعم PDF ورق A4 وA3 أفقيًا. يمكن التصفية بقاعة أو طالب. اتجاه أعمدة الخريطة متسق بين العرض وPDF، وأرقام المواقع تربط الطالب بصفه وعموده الفعليين.

تقرير السعة يحفظ حالة جميع القاعات وقت اللقطة، بما فيها غير المستخدمة. تقارير الفترة المعتمدة تستخدم اللقطة المحفوظة؛ ملخص أعباء المراقبين إحصاء حي لكل تكليفات المؤسسة والعبء السابق. القوائم المصدرة ليست بديلًا عن النسخ الاحتياطي.

### 10. الحسابات والنسخ الاحتياطي

- **مدير:** البيانات والتوزيع والاعتماد وإعادة الفتح والحسابات والنسخ والاستعادة.
- **مخطط:** البيانات والتوزيع والمسودات، دون اعتماد أو إدارة حسابات أو استعادة نسخة.
- **قارئ:** العرض والتقارير وتغيير كلمة مرور حسابه فقط.

تُفحص الصلاحيات ونطاق المؤسسة في الخادم، وتُحمى نماذج التغيير بـCSRF، وتُهشّم كلمات المرور. لا يمكن إسقاط صلاحية آخر مدير.

نسخة الإعدادات JSON موقعة بمفتاح `storage/backup.key`، حتى 20 ميغابايت. تشمل بيانات المؤسسة الدراسية والخرائط ونسخها، **ولا تستبدل الحسابات أو سجل التدقيق**. يُلغى جميع رموز البوابات بعد الاستعادة ويلزم إصدارها من جديد.

احتفظ بملف `config.php` ومفتاح النسخ في مكان آمن. الاستعادة المدمجة تستهدف نفس المؤسسة والتثبيت وبنية الإصدار. للانتقال إلى جهاز جديد أو النسخ الأكبر، صدّر قاعدة MySQL كاملة عبر phpMyAdmin وانقل التطبيق ومفتاحه وملف الاتصال بأمان؛ الاستعادة الكاملة تحفظ الحسابات كذلك. اختبر الاستعادة على قاعدة منفصلة قبل اعتمادها، ولا تكشف الملفات الشخصية أو المفتاح عبر الشبكة.

## البنية والتطوير

التنفيذ PHP مباشر بطبقات مستقلة: `app/solver.php` لمحركي المقاعد والمراقبين، `services.php` للقيود والنسخ، `actions.php` لعمليات الكتابة، `reports.php` للتقارير، وصفحات RTL منفصلة. يستخدم PDO وقيود قاعدة البيانات، دون مرحلة بناء للواجهة.

الحزمة الكاملة تتضمن المكتبات وتراخيصها. عند إعادة تجهيز التبعيات من المصدر:

```bash
composer install --no-dev --prefer-dist
php check.php
php tests/solver.php
```

`composer.lock` مثبت للإصدارات ويستهدف PHP 8.2.30 كحد منصة لحل التبعيات. روابط أرشيفات GitHub تستعمل codeload الرسمي للالتزامات نفسها بدل API المحجوب في بيئة التطوير، دون تعطيل TLS أو تعديل بصمات متوقعة. بيئة الاختبار الفعلية PHP 8.4.24 وMariaDB 11.8.6 على Linux؛ لم يُجر اختبار Windows داخل هذه البيئة.

راجع `VALIDATION.md` لنتائج التحقق وحدود المطابقة.
