## تشغيل Gemini السحابي

شغّل رقيب وافتح «إعداد الذكاء الاصطناعي»، واختر Gemini، وأدخل مفتاحك محليًا، ثم اضغط «حفظ واختبار الاتصال». لا يحتاج هذا المسار إلى Ollama أو تنزيل نموذج. تُرسل النصوص والصور اللازمة إلى Google عند التدقيق؛ راجع شروط البيانات والحصة المجانية لحسابك. اسم النموذج قابل للتغيير حسب المتاح في AI Studio. لا يُغيّر التحديث اختيار المزوّد المحفوظ تلقائيًا ولا يتضمن أي مفتاح. الحزمة تتضمن الواجهة المبنية، وتصلح أيضًا لتحديث النسخة المثبتة مع الاحتفاظ بـ`data`.

نجح التحقق البرمجي من 192 اختبارًا وبناء الواجهة واختبار إعداد Gemini عبر المتصفح. لم يُجرّب اتصال بحساب Gemini حقيقي لعدم توفر مفتاح؛ الاختبار المباشر متاح داخل إعداد البرنامج.

## التشغيل المحلي الاختياري

[تنزيل تحديث الأداء المحلي 2.0.1](https://github.com/shymaammohammad-jpg/m1/raw/refs/heads/raqib-local-performance/downloads/Raqib_Local_Performance_2.0.1.zip) · [طريقة التحديث والقياس](UPDATE_LOCAL_PERFORMANCE_AR.md)

[تنزيل رقيب المحلي 2.0.0](https://github.com/shymaammohammad-jpg/m1/raw/refs/heads/raqib-local-ai/downloads/Raqib_Local_AI_2.0.0.zip) · [سجل التحقق](VALIDATION_LOCAL_AI_AR.md)

يبدأ المسار الرئيسي برفع العقد وأولياته فقط، بما فيها أرشيف ZIP، ثم يشغّل رقيب خطوات التدقيق التسع ويعدّ استمارة الفحص والتقرير مع الاقتباسات ومصادرها. عند اختيار التشغيل المحلي، يعمل النموذج عبر **Ollama على الحاسبة نفسها**، دون مفتاح API أو إرسال مستندات العقد إلى مزود سحابي. يبقى الفحص اليدوي موجودًا داخل «المراجعة التفصيلية» عند الحاجة إلى فحص النتيجة أو تعديلها.

الإعداد الافتراضي مناسب للحاسبة المحددة في الطلب: Intel Core i5-13420H، رام 8 غيغابايت ورسوميات Intel UHD مدمجة. يستخدم `qwen2.5:3b` الخفيف، ويقسم العمل إلى دفعات. قد يستغرق التدقيق المطوّل وقتًا على المعالج. حجم النموذج الصغير يحدّ جودة الاستدلال؛ المراجعة الثانية والتحقق من الاستشهادات لا يجعلان نتائجه مكافئة لنموذج كبير أو ضمانًا لصحة التدقيق القانوني.

## الاستخدام بعد الإعداد

1. افتح `start_windows.bat` واترك نافذته وOllama قيد التشغيل.
2. ارفع ملف العقد مع الأوليات، أو أرشيف ZIP يجمعها، واضغط **بدء التدقيق الآلي**.
3. يتولى رقيب استخراج البيانات وتصنيف المستندات، وتحديد التعليمات، وفحص الأعمام والبرنامج والوثائق القياسية، وتعبئة الفحص السريع، والاستعلام عن القوائم السوداء وإعداد التقرير.
4. يظهر تقدم الخطوات والنتائج المسندة والوثائق المطلوبة والتعارضات. افتح التقرير بصيغة HTML أو نزّله PDF بعد اكتمال المعالجة. لا يلزم ملء الخطوات التسع يدويًا لإخراج التقرير الآلي.

تظهر النتيجة غير المدعومة أو ذات القراءة الناقصة «تعذّر الحسم». لا تتحول الصفحات غير المقروءة أو تعذر موقع الوزارة إلى استيفاء. يتضمن التقرير الحالات غير المحسومة ولا يخفيها، ولا ينسخ توقيعًا أو ختمًا أو أسماء وأرقام الحالة النموذجية.

## الإعداد على Windows مرة واحدة

لتحديث رقيب الموجود لديك، احتفظ بمجلد `data` وانسخ ملفات الإصدار الجديد إلى مجلد البرنامج الحالي ثم أعد تشغيل التثبيت لتحديث المكتبات. تبقى مكتبة المراجع والعقود محفوظة في `data`؛ تشغيل النسخة من مجلد جديد فارغ لا ينقلها تلقائيًا.

1. فك ضغط المشروع بالكامل إلى مجلد عادي، مثل مجلد `Raqib` على سطح المكتب. لا تشغّل ملفًا من داخل ZIP أو من المسار المؤقت الذي ينشئه مستكشف Windows.
2. ثبّت [Python](https://www.python.org/downloads/windows/) بإصدار 3.12 أو 3.13 أو 3.14 مع مشغّل `py` أو خيار **Add python.exe to PATH**، و[Node.js LTS](https://nodejs.org/) بإصدار 20.19 أو أحدث.
3. افتح `install_windows.bat`. يثبت مكتبات التطبيق، ومنها عارض PDF المرفق `pypdfium2`، ومتصفح Chromium لتصدير التقرير، ويبني الواجهة ويجلب المراجع العامة المعروفة مع فحص بصماتها. لا يحذف بيانات العمل.
4. افتح **`setup_local_ai_windows.bat`**. إذا لم يكن Ollama مثبتًا، تفتح صفحة [تنزيل Ollama الرسمية](https://ollama.com/download/windows)؛ ثبّته ثم أعد فتح ملف الإعداد المحلي.
5. ينزّل الإعداد نموذج `qwen2.5:3b` مرة واحدة. حجمه من مرتبة الغيغابايت، ويظهر تقدم التنزيل في النافذة. يحفظ الإعداد مزودًا محليًا بعنوان `http://127.0.0.1:11434` دون مفتاح API.
6. للملفات الممسوحة ضوئيًا، يتأكد الإعداد من وجود **Tesseract OCR**، ويجهز لغتي العربية والإنجليزية محليًا. عند غيابه يعرض طريقة التثبيت ويتيح تشغيل Winget بموافقتك من النافذة. أمر التثبيت هو:

```powershell
winget install --id UB-Mannheim.TesseractOCR -e --source winget
```

يمكن اتباع [تعليمات Tesseract لويندوز](https://github.com/UB-Mannheim/tesseract/wiki) إذا لم يتوفر Winget. أعد الإعداد المحلي بعد تثبيته. لا يحتاج عرض PDF إلى Poppler على Windows، لأن PDFium مثبت ضمن مكتبات التطبيق. النموذج الافتراضي نصي؛ قراءة الصور تعتمد على OCR المحلي، ولا تُرسل إلى خدمة خارجية عند غياب محرك القراءة.

يحتاج تنزيل البرامج والنموذج واللغة والمراجع إلى الإنترنت في الإعداد الأول. بعد ذلك تجري قراءة العقود وتحليلها محليًا. خطوة القوائم السوداء تحتاج الاتصال بموقع وزارة التخطيط؛ عند تعذرها يسجل التقرير ذلك صراحة. ولا يشكل غياب الاسم من مصدر محدود شهادة خلو رسمية.

في المرات اللاحقة يكفي `start_windows.bat`. يشغل الخدمة باسم الحزمة `backend.app`، ويعالج خطأ `attempted relative import with no known parent package`؛ لا تحتاج إلى تعديل أسطر الاستيراد أو إعادة التثبيت في كل مرة.

إذا أخفق تنزيل المراجع العامة، يمكن رفعها من مكتبة المراجع أو إعادة المحاولة:

```bat
.venv\Scripts\python.exe scripts\sync_references.py
```

## الإعداد على Linux

```bash
bash scripts/install.sh
ollama pull qwen2.5:3b
bash scripts/start.sh
```

ثبت Ollama وTesseract وأدوات النظام حسب توزيعتك أولًا. تثبيت Linux الحالي يتحقق أيضًا من Poppler وChromium وخطوط العربية. تخزن لغة OCR المحلية في `data/tessdata` وتتحقق بصمة النموذج العربي قبل اعتماده.

للواجهة أثناء التطوير: نفذ `npm run dev` داخل `frontend`. يمرر Vite طلبات `/api` إلى الخدمة الخلفية. الخدمة المحلية الافتراضية على `127.0.0.1:8000`، ويمكن تغيير المنفذ بواسطة `AUDIT_PORT` أو `python run.py --port 8001`. هذا تطبيق محلي لمستخدم واحد، وليس خدمة متعددة المستخدمين جاهزة للنشر العام.

## كيف يجري التدقيق

- استخراج صفحات PDF كاملة ضمن حدود القراءة، بما فيها الصفحات المصورة، مع فهرسة الصفحة والبصمة وملاحظات القراءة. ترقيم Word والنصوص مقاطع منطقية، ويُوسم كذلك؛ لا يُدّعى أنه ترقيم صفحات Word المطبوعة.
- استخراج بيانات العقد من اقتباسات فعلية، وعدم اختيار قيمة صامتًا عند وجود قيم متعارضة. لا تُملأ هوية شخص أو تاريخ أو مبلغ من التخمين.
- تنفيذ بنود البرنامج على المقاطع ذات الصلة من العقد والمراجع، ثم التحقق برمجيًا من المستند والصفحة والاقتباس وتصنيف المرجع وسنته.
- إجراء مراجعة ثانية بالذكاء الاصطناعي للنتائج وإجابات الاستمارة. هذه جولة مراجعة أخرى للنموذج نفسه، وليست ضمانًا باستقلال أخطائه أو شهادة لصحة الاستنتاج.
- حفظ المصادر الأصلية وبصماتها، وربط كل تقرير بالتشغيل ومدخلاته. تعديل العقد أو المرفقات أو المراجع يستلزم إعادة التدقيق قبل إخراج تقرير حالي.
- حفظ استعلامات الوزارة ومصادرها وتوقيتها، مع التمييز بين مصدر حي وقائمة مرفوعة أو قديمة.

المسار اليدوي السابق يحتفظ بقيوده الخاصة لاعتماد تقريره. التقرير الآلي يعرض النواقص والتحفظات دون اشتراط إكمال حقول بشرية أو اختلاق توقيع مسؤول.

## البيانات والإعدادات

تحفظ العقود والمرفوعات وقاعدة SQLite وإعدادات النموذج وصفحات القراءة والتقارير في `data/` المستثنى من Git. يمكن عزلها بواسطة `AUDIT_DATA_DIR`. إعدادات المزود المحلية في `data/ai_settings.json`؛ لا تُعرض المفاتيح في نتائج API أو التقرير. الخيار المحلي لا يحتاج مفتاحًا، ولا يستخدم مزودًا سحابيًا تلقائيًا عند فشل النموذج.

توجد إعدادات اختيارية موثقة في `.env.example`. هذا ملف أمثلة وليس ملفًا يحمّله المشغّل تلقائيًا؛ اضبط المتغيرات في نافذة التشغيل أو استخدم إعداد الذكاء الاصطناعي في الواجهة. متغيرات البيئة لها الأولوية على الإعداد المحفوظ. العنوان المحلي يقبل loopback فقط؛ لا تجعل Ollama يستمع على الشبكة العامة.

حدود الأمان الأساسية: 100 ميغابايت للملف، و200 عنصر في الأرشيف و250 ميغابايت بعد الفك، مع رفض المسارات الخطرة والروابط والضغط المفرط. لقراءة المستندات والطلبات حدود إضافية موضحة في نتائج التغطية. لا تُنفذ التعليمات أو الشيفرات الموجودة داخل المستندات، ولا تعتبر وثائق العقد تعليمات للمساعد.

## المراجع والقواعد الزمنية

- تصف `reference_structure.json` هيكل التدقيق والاستمارة، و`reference_circulars.json` الأعمام والقرارات، و`reference_report.json` ترتيب أقسام التقرير البشري وجداوله.
- لا تتضمن نسخة Git المرفقات الأصلية الأربعة أو عقود المستخدم. ارفعها من مكتبة المراجع، أو انقل `data/reference_library/` وmanifest من نسخة موثوقة دون نقل قاعدة بيانات العقود إلى جهة أخرى دون قصد.
- يستطيع `scripts/sync_references.py` جلب المراجع العامة المعروفة والتحقق من SHA-256، ويحافظ على مراجع المستخدم. تشمل المكتبة المعدة تعليمات 2014 بتنقيح تموز 2017، والوقائع العراقية 4849 وتعليمات 2025، وحزمة 3429 والضوابط والتعديلين المعروفين لعام 2024. لا يدعي هذا جمع جميع التعديلات الممكنة.
- قاعدة المستخدم الافتراضية: عقد 2024 ← تعليمات 2014؛ ومن 2025 إلى السنة الحالية ← تعليمات 2025. لا تعني القاعدة وحدها ثبوت النفاذ. المادتان 41 و42 من تعليمات 2025 وكتاب الوزارة 3429 في 3/2/2026 يقتضيان فحص النفاذ واستمرار التعليمات السابقة؛ يذكر الكتاب بدء التطبيق في 15/2/2026.
- بعض الأعمام تخص آب 2026، ويتضمن دليل رئيس الوزراء نظامًا سابقًا ملغى. لا يجوز إسقاط أحكامها على العقود الأقدم أو نقل حد 25 مليار أو مدة 30 يومًا من النظام الملغى بوصفها قاعدة حالية تلقائيًا. تظهر الإحالات المتعارضة أو غير المحسومة في النتيجة.
- الموقع الرسمي لوزارة التخطيط نفسه ينبه إلى الرجوع للدائرة المختصة لتأكيد الموقف القانوني. القوائم التاريخية أو قرار إدراج أو رفع منفرد لا يثبت مراجعة القائمة الحالية كاملة.

## التقرير والاختبار

يحافظ الإخراج على ترتيب «الإيضاحات» و«الملاحظات» وأسماء أقسام وجداول النموذج البشري، مع ملحق الاستمارة وفهرس الأدلة والتغطية. المصدر PDF ممسوح لحالة سابقة؛ إعادة التنضيد ليست مطابقة بصرية حرفية، ولا يُنسخ توقيع أو ختم أو وقائع تلك الحالة. يظل اتخاذ الإجراء الرسمي من صلاحية الجهة المخولة.

```bash
.venv/bin/python -m unittest discover -s tests -v
cd frontend
npm run build
```

تشمل الاختبارات ملفات اصطناعية معزولة، وبروتوكول المزود بالمخرجات المنظمة، وربط الأدلة، والمراجعة الثانية، وتسلسل الخطوات، وإبطال التقارير القديمة وتصدير PDF عربي. لا تثبت الاختبارات صحة تدقيق عقد حقيقي أو دقة نموذج محلي على حاسبة Windows ذات 8 غيغابايت. راجع ملاحظات التغطية والاستشهادات عند استعمال أي نتيجة فعلية.
